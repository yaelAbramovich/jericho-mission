# מבצע יריחו – PWA ללימוד יהושע א׳–ה׳
קבצים סטטיים בלבד, בלי build. להרצה מקומית: `python3 -m http.server 8765` והכתובת http://localhost:8765. הוראות בעברית להורה: `הוראות.html`.

## מסגרת המקצועות (framework)
האפליקציה היא מנוע כללי, וכל מבחן הוא **חבילת מקצוע** (pack) בתיקייה משלה: `js/subjects/<id>/`. המנוע (משחקים, פס קרב, עונות, פרסים, אפקטים) משותף, ובכל חבילה יש רק את התוכן והעיצוב של המבחן:
- `pack.js` – ה"חוזה": שם, תאריך מבחן, `units` (אזורי המפה: n, zone, title, story), `topics` (חומר "למבחן"), `duels` (דו-קרב + `duelUnits`), `statements` (אמת/שקר), `sequences` (סידור), `glossary`, `map` (מיקומי אזורים + רקע SVG), `games` (אילו משחקים ואופנים פעילים), `labels` (טקסטים כמו "פרק"/"יחידה"). אופציונלי: `quotes`+`who`+`refText` (משחקים מבוססי פסוקים), `boss`, `overview`, `examSequences`.
- הדוגמאות: `joshua/` (מלאה) ו-`science/` (חבילת דוגמה קטנה, בלי פסוקים ובלי "מי אמר" – מראה שהמנוע לא תלוי ביהושע).
- **להוספת מקצוע**: מעתיקים את `science/`, ממלאים תוכן, רושמים ב-`REGISTRY` (`js/subjects/index.js`; `hidden: true` מסתיר מהבורר עד שהתוכן מוכן) ובקבצי `sw.js`. בדיקת "חוזה החבילה" ב-`npm test` מאמתת אותה אוטומטית.
- הפרסים (XP, פריטים, עונות) משותפים לכל המקצועות; האזורים, התדריכים והמבחן נשמרים לכל מקצוע בנפרד (`state.subjects`).
- יהושע: `js/subjects/joshua/` (ושאלות נוספות ב-`bank/`).

כל משחק ב-`js/games/*.js` מייצא `run(el, opts, scope) → Promise<תוצאה>`; רושמים אותו ב-`ALL_GAMES` ב-`js/app.js`. אחרי שינוי קבצים מעלים את VERSION ב-`sw.js`.

בדיקות: `npm install && npx playwright install chromium && npm test` (או `npm run test:fast` – רק פרק ב׳). הבדיקות טוענות כל קובץ JS בדפדפן אמיתי, פותחות כל מסך, משחקות כל משחק מההתחלה עד הסוף בכל פרק, ובודקות את התוכן, התגמולים וההעתקה. **להריץ לפני כל commit** – `node --check` לא מספיק לקבצי ES-module (הוא לא תופס הגדרה כפולה של משתנה).
